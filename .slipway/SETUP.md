# taskflow — what a human does, and what slipway automates

Generated by slipway (1.6.0). `/slipway:launch` runs everything below that is marked *automated*; it stops at the *human* items and tells you exactly what to do. Re-run it after each human step, it continues where it left off.

| Step | Who | How |
|---|---|---|
| Sign in to Azure with an identity that can create resources in the subscription and assign roles in its resource group | human | `az login && az account set --subscription <id>` (subscription and tenant ids stay out of this public repo) |
| Sign in to GitHub with rights to set repository secrets and environments | human | `gh auth login` |
| Docker Hub account with access to Docker Hardened Images: username and an access token | human | copy the token to the clipboard, or copy `.slipway/.env.example` to `.slipway/.env` (gitignored) and fill it; then `docker login dhi.io` happens from the seed file without printing anything |
| Authorise the Atlassian Rovo MCP Server once | human | `/mcp` → `atlassian` in the session (headless runs reuse the grant) |
| Entra app registration with OIDC federated credentials for `integranz/taskflow` (branch `main`, environment `dev`), Terraform state storage (Entra-only auth), resource group `rg-taskflow-dev`, least-privilege role assignments | automated, behind one permission prompt | `bash .slipway/setup-azure.sh --apply --set-github-secrets` (dry run without `--apply`); also writes the identifier secrets `AZURE_CLIENT_ID`, `AZURE_TENANT_ID`, `AZURE_SUBSCRIPTION_ID` |
| Repository secret `DOCKERHUB_TOKEN` and variable `DOCKERHUB_USERNAME` | automated from the clipboard or the seed file, behind a permission prompt | `gh secret set DOCKERHUB_TOKEN -R integranz/taskflow --body "$(pbpaste)"`, `gh variable set DOCKERHUB_USERNAME …` |
| GitHub environment `dev` with you as required reviewer and deployments from `main` only | automated, behind a permission prompt | `gh api -X PUT repos/integranz/taskflow/environments/dev …` |
| Branch ruleset on `main`: pull requests only, required checks `api changes`, `api ci` | automated, behind a permission prompt | `node <plugin>/scripts/ruleset.cjs \| gh api -X POST repos/integranz/taskflow/rulesets --input -` |
| Foundation infrastructure (registry `acrtaskflowdev`, key vault `kv-taskflow-d1`, identity, logs, Container Apps environment) | automated plan; the apply waits for your answer to the permission prompt that shows the plan summary | `/slipway:plan dev --layer foundation` then `terraform -chdir=infra/foundation apply tfplan.dev` (unattended sessions need `scripts/approve-apply.sh` instead) |
| Key Vault secret `database-url` (the app reads it as `DATABASE_URL`) | **human value**, after the foundation apply: put `DATABASE_URL=…` in `.slipway/.env` and let the agent write it behind a permission prompt (the value is never shown), or run the command yourself. The app layer cannot deploy until it exists | `set -a; . .slipway/.env; set +a; az keyvault secret set --vault-name kv-taskflow-d1 --name database-url --value "$DATABASE_URL"` |
| Deployments | automated per app; each waits for the `dev` approval on the workflow run page | `taskflow-<app>-cd` |

## Facts to know
- Federated credentials use GitHub's immutable subject format `repo:<owner>@<id>/<repo>@<id>:…`; `setup-azure.sh` reads the repository's setting and writes the right subjects, and repairs them after a repository rename.
- The state storage account disables shared-key access; Terraform authenticates with Entra ID (`use_azuread_auth = true`, `ARM_USE_AZUREAD=true`).
- The CI/CD principal holds `Contributor` on `rg-taskflow-dev`, `Storage Blob Data Contributor` on the state container and `AcrPush` on the registry (assigned by the foundation layer). Nothing privileged (Owner, User Access Administrator) is ever assigned by slipway.
- Check anything with: `gh secret list -R integranz/taskflow`, `gh variable list -R integranz/taskflow`, `gh api repos/integranz/taskflow/environments/dev --jq '.protection_rules[].type'`, `bash .slipway/setup-azure.sh` (dry run), or simply `bash <plugin>/scripts/preflight.sh`.
